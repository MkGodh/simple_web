Simple Web Proxy

##  О проекте

**Simple Web Proxy** — проект на C++, в котором я реализовал асинхронный TCP-прокси сервер на базе Boost.Asio.

Цель проекта — разобраться, как устроены сетевые прокси на низком уровне:
как клиентское соединение “перетекает” через промежуточный сервер и проксируется на удалённый endpoint без блокировок.

Проект построен как экспериментальная сетeвая лаборатория, где тестируются:

- асинхронная модель I/O
  
- управление TCP-соединениями
  
- двусторонний поток данных
  
- архитектура proxy relay

## Что делает проект:
- Проект реализует простой TCP proxy по схеме:

      - Client  →  Proxy Server  →  Remote Server

                     (8080)            (9090)

      - Client  ←  Proxy Server  ←  Remote Server
Proxy выступает как промежуточный слой, который:

- принимает соединение клиента
- устанавливает соединение с удалённым сервером
- проксирует данные в обе стороны в реальном времени

##  Архитектура
  Проект разделён на 3 независимых компонента:

### **gdhClient**
  TCP-клиент:
  - подключается к proxy (127.0.0.1:8080)
  - читает поток данных
  - выводит результат в консоль

### **gdhServer (Proxy)**
Основной компонент проекта:
  - принимает входящие TCP соединения
  - создаёт PROXYConnection
  - подключается к remote server (9090)
  - запускает двусторонний обмен:

     Client → Remote

     Remote → Client
 
  ### **gdhTestServer (Remote server)**
  Тестовый сервер:
  - слушает порт 9090
  - отправляет тестовые данные в соединение
  - используется как “имитация внешнего сервера”
  
---

## Как работает прокси внутри

После подключения:

- Клиент подключается к proxy (8080)
- Proxy создаёт соединение с remote server (9090)
- Запускаются два асинхронных потока:
- клиент → remote
- remote → клиент
- Данные начинают непрерывно “протекать” через proxy

#  Особенности реализации

Этот проект демонстрирует:
- асинхронную неблокирующую модель I/O
- управление временем жизни объектов через shared_ptr
- построение TCP relay без сторонних протоколов
- обработку ошибок соединений
- простую реализацию proxy pipeline 

# ⚠️ Ограничения

- нет HTTP parsing 
- нет TLS / HTTPS tunneling  
- нет packet framing (stream-based TCP)  
- нет production logging
- нет load balancing
