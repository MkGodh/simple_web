Simple Web (TCP Server/Client on Boost.Asio)

##  О проекте

**Simple Web Proxy** — проект на C++, в котором я реализовал асинхронный TCP-прокси сервер на базе Boost.Asio.

Цель проекта — разобраться, как устроены сетевые прокси на низком уровне:
как клиентское соединение “перетекает” через промежуточный сервер и проксируется на удалённый endpoint без блокировок.

Проект построен как экспериментальная сетeвая лаборатория, где тестируются:

-асинхронная модель I/O
-управление TCP-соединениями
-двусторонний поток данных
-архитектура proxy relay

Возможности проекта:
- Асинхронный TCP-сервер (Boost.Asio)
- Обработка нескольких соединений одновременно 
- TCP-прокси (двусторонний поток данных)
- Relay архитектура: Client ↔ Proxy ↔ Remote Server
- Тестовый удалённый сервер
- Работа без блокирующих операций
- Управление жизненным циклом соединений через std::shared_ptr  
- Разделение логики:
-сервер соединений
-прокси-обработчик
-тестовый удалённый сервер

##  Архитектура
- Проект состоит из трёх компонентов:
###  Сервер

- **Client**
  - Принимает входящие подключения
  - Использует `boost::asio::async_accept`
  - Хранит список активных соединений

- **TCPConnection**
  - Представляет одно клиентское соединение
  - Отправляет сообщение клиенту
  - Обрабатывает отключение клиента
 
  - **PROXYConnection**
  - Реализует две независимые цепочки передачи данных:
  - Client → Remote : Client → Proxy → Remote Server
  - Remote → Client:  Remote Server → Proxy → Client
  - Каждое направление работает независимо через собственный буфер:
    buff_client
    buff_remote

###  Клиент

- Подключается к `127.0.0.1:8080`
- Читает данные от сервера в бесконечном цикле
- Выводит полученные сообщения в консоль

# Запуск

## Запуск сервера
```bash
./gdhServer
```

Сервер начнёт слушать порт **8080**

## Запуск клиента
```bash
./gdhClient
```

Если всё успешно:


```text
Connected!
```
# Как это работает

## Сервер
- Запускается и ждёт подключения
- Клиент подключается
- Создаёт `TCPConnection`
- Отправляет сообщение (`async_write`)

## Клиент
- Получает данные (`read_some`)
- Выводит их в консоль

#  Особенности реализации

- Используется `shared_from_this()` для безопасной работы с async callbacks  
- Асинхронная модель без блокировок  
- Сервер поддерживает несколько клиентов  
- Используется `io_context` как ядро событий  

# ⚠️ Ограничения

- Сервер не обрабатывает входящие сообщения от клиента  
- Нет протокола передачи данных  
- Нет многопоточности  
- Соединения не удаляются из контейнера  

#  Возможные улучшения
